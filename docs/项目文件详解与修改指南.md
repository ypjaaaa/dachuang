## 二、核心代码逐个讲(app/ 目录)

### 2.1 config.py —— 全局配置(70 行)
**职责**:整个项目的中枢,所有路径、模型、参数都在这里。

| 变量 | 作用 | 想改什么 |
|---|---|---|
| `BASE_DIR` / `MODELS_DIR` / `DATA_DIR` | 路径 | 一般不用动 |
| `ASR_MODEL` | 转写模型路径 | 换转写模型改这里(指向本地目录) |
| `EMBED_MODEL` | 嵌入模型路径 | 换嵌入模型改这里 |
| `RERANK_MODEL` | 重排模型路径 | 换重排模型改这里 |
| `LLM_GGUF` | 问答大模型文件 | 换问答模型改这里 |
| `DEVICE` | torch 设备(cuda/cpu,自动检测) | 强制 CPU/GPU 改这里 |
| `ASR_DEVICE` | 转写设备(固定 cpu) | GPU 转写修好后改这里 |
| `LLM_GPU_LAYERS` | LLM GPU 层数(固定 0) | 重编译 CUDA 版后改 -1 |
| `COLLECTION` / `VECTOR_DIM` | 向量库集合名 / 维度 | 换模型时同步改维度 |
| `TOP_K` / `VEC_TOP_K` / `BM25_TOP_K` / `RERANK_TOP` / `MIN_SCORE` | 检索参数 | **调检索准确率重点改这里** |
| `LLM_CTX` | 大模型上下文长度 | 长文本改大 |

⚠️ 顶部有一段"预加载 libcublas.so.12"的代码(ctypes),是为 GPU 转写预留的,现在 ASR 走 CPU,这段不影响运行,可留可删。

### 2.2 asr.py —— 语音识别(46 行)
**职责**:把音频变成带时间戳的文字。
- `get_model()`:加载 faster-whisper large-v3(int8 量化,`device=config.ASR_DEVICE`)
- `transcribe(audio_path)`:转写,返回 `[{start, end, text}]`
- **想改转写模型**:改 config 的 `ASR_MODEL`(如换成 medium 模型转写更快)
- **想改转写语言/参数**:改 `transcribe()` 里的 `language`、`beam_size`、`vad_filter`

### 2.3 chunk.py —— 智能分块(58 行)
**职责**:把转写出的句子合并成"知识块",每块保留时间戳。
- `chunk_segments(segments)`:按句号/长度阈值切分,超长段递归切分
- `MAX_CHARS=500` / `OVERLAP=80`:目标块大小和重叠
- **想改分块粒度**:改这两个常量(块越小检索越精确但信息碎片化)

### 2.4 embed.py —— 向量嵌入(27 行)
**职责**:文字 → 1024 维向量(bge-large-zh-v1.5)。
- `get_model()`:加载嵌入模型
- `embed_texts(texts)`:批量编码,归一化
- 改模型记得同步改 config 的 `VECTOR_DIM`

### 2.5 retriever.py —— 混合检索(120 行)⭐
**职责**:检索环节的核心,四步:向量+BM25 → RRF 融合 → Rerank 精排 → 阈值过滤。
- `HybridRetriever` 类:
  - `_load_corpus()`:从 Milvus 拉全部文本建 BM25 索引
  - `_vec_search()`:向量检索 top-20
  - `_bm25_search()`:BM25 关键词检索 top-20(jieba 分词)
  - `_rrf_fuse()`:RRF 排名融合
  - `_rerank()`:bge-reranker 精排 top-30 候选
  - `search(query, top_k)`:对外主入口
- **想调检索效果**:改 config 的 `TOP_K/VEC_TOP_K/BM25_TOP_K/RERANK_TOP/MIN_SCORE`,或这里的分词/融合逻辑

### 2.6 ingest.py —— 入库管道(122 行)
**职责**:一条命令完成"音频→转写→分块→嵌入→入库"。
- `_client()`:连接 Milvus Lite,建集合(1024 维、字符串主键)
- `ingest(audio_path, title, date)`:主流程,返回入库块数
- 命令行用法:`python -m app.ingest 音频 "标题" "日期"`
- **想改存储字段**:改 `_client()` 的建集合和 insert 的字段

### 2.7 query.py —— 问答编排(77 行)
**职责**:把检索结果和问题组装给大模型,返回带引用的答案。
- `retrieve()`:调混合检索 + 阈值过滤
- `build_prompt()`:组装 system + 摘录(带时间戳)+ 问题
- `answer(query, history)`:完整问答(支持多轮),返回 `{answer, citations, search_query}`
- **想改提示词**:改 `SYSTEM_PROMPT`(控制回答风格/防幻觉)
- **想改"未找到"提示**:改 answer() 里的返回文案

### 2.8 llm.py —— 本地大模型(75 行)
**职责**:加载 Qwen2.5-7B GGUF,负责回答生成和多轮重写。
- `load_llm()`:加载 llama-cpp 模型(懒加载,首次问答才加载)
- `generate(system, user)`:聊天接口生成回答
- `rewrite_query(history, question)`:多轮对话的追问重写(用拼接文本方式,避开模板 bug)
- **想换问答模型**:改 config 的 `LLM_GGUF`(重新下载 GGUF 放 models/llm/)
- **想调回答风格**:改 `generate()` 的 `temperature`(越高越发散)

### 2.9 server.py —— FastAPI 后端(81 行)★正式界面
**职责**:提供网页 API,替代旧 Gradio。
| 接口 | 功能 |
|---|---|
| `GET /` | 返回前端页面(static/index.html) |
| `POST /api/ingest` | 上传音频/录音 → 转写入库(webm 自动转 wav) |
| `POST /api/answer` | 问答(JSON,带 history) |
| `GET /api/status` | 健康检查 + 设备状态 |
- 启动:`python -m app.server` → http://127.0.0.1:7860
- **想加接口**:照葫芦画瓢加 `@app.post("/api/xxx")`

### 2.10 ui.py —— 【旧】Gradio 界面(230 行)
⚠️ **已被 server.py 替代,当前不使用了**。保留是怕你想回退。想删可以删,删了 start.sh 也要改。

### 2.11 evaluate.py —— 检索评测(42 行)
**职责**:用标注测试集量化检索准确率(PPT 指标 ≥80%)。
- `TEST_SET`:测试题列表(问题 → 期望命中的段落)
- `evaluate()`:跑检索,算准确率
- **想加测试题**:往 `TEST_SET` 里加 `(问题, [["会议标题", 起始秒]], 备注)`
- 运行:`python -m app.evaluate`

### 2.12 download_models.py —— 模型下载(55 行)
**职责**:从 ModelScope 下载全部模型(国内可访问)。
- `REPOS`:模型仓库列表
- `download_llm_gguf()`:下载 Qwen GGUF(Q4_K_M 分片)
- 运行:`python -m app.download_models`(asr/embed/llm/all 可选)

### 2.13 debug_qa.py —— 诊断脚本(20 行)
**职责**:跑一次问答,把完整错误存到 qa_debug.txt(排障用)。运行:`python -m app.debug_qa`

## 三、前端:static/index.html(你要美化的)

单文件前端(HTML+CSS+JS),没有构建步骤,改完刷新即生效。

### 结构
```
<nav>      顶部导航(Logo/标题/徽章/主题切换)
<div.main>
  <aside>  左面板:上传 + 现场录音 + 标题日期 + 转写按钮
  <section>右面板:聊天列表 + 输入框
<div.foot> 页脚
<script>   JS:主题切换/录音/上传/聊天/引用渲染
```

### 想改什么,找哪

| 想改 | 位置 |
|---|---|
| **配色** | `<style>` 里 `:root{...}`(浅色)和 `body.dark{...}`(深色),改 `--brand`、`--bg` 等变量即可整套变色 |
| **渐变主色** | `--grad: linear-gradient(...)` 改颜色值 |
| **圆角/阴影** | `--radius`、`--shadow` 变量 |
| **字体** | `body` 的 `font-family` |
| **顶部徽章文字** | nav 里的 `<span class="chip">` |
| **上传区文字/图标** | `.upload-zone` 里的 HTML |
| **录音功能** | JS 里 `recBtn.onclick`(MediaRecorder 逻辑) |
| **聊天气泡样式** | `.msg.user .bubble`、`.msg.bot .bubble` |
| **引用标签样式** | `.cite-item` |
| **页面文案** | 各处 HTML 文本直接改 |
| **新增功能** | 加 HTML + 在 `<script>` 加 JS + 对应后端接口 |

### 前端 ↔ 后端接口(JS 里的 fetch 调用)
- `POST /api/ingest`(FormData:file/title/date)→ 转写入库
- `POST /api/answer`(JSON:question/history)→ 问答
- `GET /api/status` → 设备状态

## 四、启动方式(重要)

### ✅ 正式方式(新界面,推荐)
```bash
cd ~/桌面/大创
CUDA_VISIBLE_DEVICES=0 nohup ./venv/bin/python -m app.server > server_log.txt 2>&1 &
# 打开 http://127.0.0.1:7860
```

### ⚠️ start.sh(你写的,启动的是旧 Gradio)
`start.sh` 里 `exec "$PY" -m app.ui` 启动的是 **ui.py(旧界面)**。建议改成 server:
```bash
exec "$PY" -m app.server
```
(改这一行即可,代理清理逻辑保留,server 也需要)

### Docker 方式
```bash
docker compose up -d   # 镜像内代码是旧版,需重新 build 才包含新前端
```
