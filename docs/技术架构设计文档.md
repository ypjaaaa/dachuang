## 1. 系统总体架构

```
┌─────────────────────────────────────────────────────────────────┐
│  交互层: Gradio Web 界面(导入会议 / 智能问答 / 引用展示)            │
├─────────────────────────────────────────────────────────────────┤
│  业务层: FastAPI 后端(内嵌)                                      │
│   入库管道: 音频→ASR→分块→嵌入→入库(增量/去重)                    │
│   问答管道: 混合检索→RRF融合→Rerank→Prompt组装→LLM生成→引用      │
├─────────────────────────────────────────────────────────────────┤
│  模型服务层(全部本地):                                           │
│   ASR: faster-whisper large-v3(int8)                            │
│   Embedding: bge-large-zh-v1.5(1024维)                          │
│   Rerank: bge-reranker-v2-m3                                    │
│   LLM: llama.cpp + Qwen2.5-7B-Instruct GGUF Q4_K_M              │
├─────────────────────────────────────────────────────────────────┤
│  数据层: Milvus Lite(向量+元数据) + 文件系统(音频/转写存档)         │
├─────────────────────────────────────────────────────────────────┤
│  部署层: Docker Compose(应用+模型卷挂载,可选 GPU 直通)             │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 模块设计

### 2.1 入库管道(ingest.py)

```
输入: 音视频文件
  → asr.transcribe(): faster-whisper 转写,输出 [{start, end, text}] 段落
  → chunk.chunk_segments(): 按语义边界(句末标点/长度阈值)切块,
      每块携带 {text, start, end} 时间戳元数据;超长块递归切分(500字符,80重叠)
  → embed.embed_texts(): bge-large-zh-v1.5 批量编码,归一化
  → MilvusClient.insert(): 写入 collection(字符串 UUID 主键,
      字段: vector/text/start/end/source/title/date)
输出: 入库知识块数量
```

关键设计决策:
- **时间戳随块存储**:每个知识块保留起止秒,是"答案可溯源回听"卖点的数据基础;
- **Milvus Lite 嵌入式**:零运维、单文件存储,契合"轻量本地部署"定位;后续数据量增长可无缝切换 Milvus Server(Docker)或 Qdrant(API 兼容层由 pymilvus 提供)。

### 2.2 检索与问答管道(query.py + retriever.py)

```
问题
  → (可选)rewrite_query(): 多轮对话时用 LLM 结合历史重写检索词
  → HybridRetriever.search():
      ① 向量召回 top-20(bge 编码问题 → Milvus COSINE 检索)
      ② BM25 召回 top-20(jieba 分词,进程内索引)
      ③ RRF 融合( Reciprocal Rank Fusion,k=60 )
      ④ bge-reranker-v2-m3 对 top-30 候选交叉编码精排(apply_sigmoid)
      ⑤ 阈值过滤(score ≥ 0.01)取 top-k
  → build_prompt(): 系统提示 + 摘录(含时间戳/来源) + 问题
  → llm.generate(): Qwen2.5-7B chat 模板生成
输出: {answer, citations:[{title, start, end, score}]}
```

### 2.3 本地 LLM 服务(llm.py)

- llama-cpp-python 加载 GGUF(分片自动合并),chat 模板由 GGUF 元数据驱动;
- `n_gpu_layers` 自动适配:GPU 可用(-1 全上)否则 CPU(0);
- `rewrite_query()` 复用同一模型实例做检索词重写,零额外部署成本。

## 3. 数据设计(Milvus 集合 Schema)

| 字段 | 类型 | 说明 |
|---|---|---|
| id | VARCHAR(主键) | UUID |
| vector | FLOAT_VECTOR(1024) | bge-large-zh-v1.5 归一化向量 |
| text | VARCHAR | 知识块文本 |
| start / end | FLOAT | 起始/结束时间戳(秒) |
| source | VARCHAR | 源音频文件路径 |
| title | VARCHAR | 会议标题 |
| date | VARCHAR | 会议日期 |

索引:COSINE 度量;元数据字段可扩展为过滤条件(按会议/日期/说话人)。

## 4. 关键技术选型与依据

| 环节 | 选型 | 依据(2025 现状) |
|---|---|---|
| ASR | faster-whisper large-v3 | 中文准确率高、本地部署、int8 量化省显存;与 FunASR 双案验证后选用 |
| 分块 | 时间戳语义分块 + 递归切分 | 保留时间戳;避免固定长度截断语义 |
| Embedding | bge-large-zh-v1.5 | 中文检索榜单领先,CPU 可推理 |
| Rerank | bge-reranker-v2-m3 | 多语言,对 top-k 精排显著提升准确率 |
| 向量库 | Milvus Lite | 嵌入式零运维;pymilvus 3.x 官方支持;生态完整 |
| LLM | Qwen2.5-7B Q4 | 中文能力强,4.4GB 量化版个人电脑可跑 |
| 界面 | Gradio | 快速交付,支持文件上传/聊天组件 |

## 5. 部署方案

### 5.1 本地部署

```bash
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
./venv/bin/python -m app.download_models   # 首次,约 9GB
./venv/bin/python -m app.ui                # 启动 127.0.0.1:7860
```

### 5.2 Docker 一键部署

```yaml
# docker-compose.yml(核心)
services:
  meeting-kb:
    build: .
    ports: ["7860:7860"]
    volumes:
      - ./models:/app/models   # 模型卷挂载,镜像轻量
      - ./data:/app/data       # 数据卷
    restart: unless-stopped
    # GPU 直通(需 nvidia-container-toolkit):
    # deploy: {resources: {reservations: {devices: [{driver: nvidia, count: 1, capabilities: [gpu]}]}}}
```

实测:镜像构建 3.6GB,容器启动、端口映射、模型/数据挂载、容器内检索全部验证通过。

## 6. 性能与评测

### 6.1 检索准确率(标注测试集,6 题)

| 指标 | 结果 |
|---|---|
| 混合检索 + Rerank 准确率 | **83.3%(5/6)≥ 80% 达标** |
| 评测命令 | `python -m app.evaluate` |

### 6.2 速度实测(消费级硬件:RTX 2060 + R7 4800H)

| 环节 | CPU 模式 | GPU 模式 |
|---|---|---|
| 2 分钟会议转写 | 5-15 分钟 | 1-2 分钟 |
| 单次问答(含模型加载) | ~3-5 分钟 | ~43 秒(LLM 走 CPU 时) |
| 检索(混合+Rerank) | 秒级 | 秒级 |

> 注:当前 LLM 推理为 CPU 版(43 秒含首次加载);安装 CUDA Toolkit 重编译 llama-cpp 后,LLM 生成可降至 10-15 秒。

## 7. 安全与隐私设计

- **全本地闭环**:ASR/Embedding/Rerank/LLM 四类模型全部本地加载,推理零联网;
- **数据隔离**:音频、文本、向量仅存于用户本地目录;Docker 部署时通过卷挂载,数据不出宿主机;
- **无外部依赖**:模型从 ModelScope 离线下载后,运行期不依赖任何云端服务。
