## 二、软件概述

### 2.1 开发背景

高校课题组组会、课程讲座等场景产生的音视频内容,往往因为缺乏有效的记录与检索手段而被"封存"在非结构化文件中:会后难以追溯讨论细节,想要快速定位某个知识点只能反复拖动进度条,数据隐私敏感内容又不便上传云端 AI 服务。

### 2.2 软件定位

本软件是一款**轻量级、可本地部署的会议知识管理工具**,基于 RAG(检索增强生成)技术,将会议音视频自动转写为带时间戳的文本,构建向量知识库,支持自然语言智能问答,并保证**数据全程本地存储、不上传云端**。

### 2.3 核心功能

1. **会议音频自动转写**:支持 MP3/WAV/M4A 等主流格式,输出带时间戳的逐句文本;
2. **智能文本分块**:按语义切分长文本,每个知识块携带起止时间戳与来源元数据;
3. **向量知识库构建**:文本向量化后存入本地向量数据库,支持增量入库;
4. **自然语言智能问答**:基于 RAG 技术,回答前先从知识库检索相关会议内容,答案带来源引用(可定位到原始音频的秒级时间点);
5. **多轮对话**:支持追问,自动结合上文补全检索上下文;
6. **会议要点总结**:可对转写全文进行结构化摘要(扩展功能)。

### 3.1 环境要求

| 项目 | 最低配置 | 推荐配置 |
|---|---|---|

### 3.2 安装步骤

1. 安装系统依赖:`sudo apt install -y ffmpeg python3.12-venv`
2. 创建虚拟环境:`python3 -m venv venv && ./venv/bin/pip install -r requirements.txt`
3. 下载模型(首次约 9GB):`./venv/bin/python -m app.download_models`
4. 启动软件:`./venv/bin/python -m app.ui`,浏览器访问 `http://127.0.0.1:7860`

### 3.3 Docker 部署(可选)

```bash
docker compose up -d   # 一键启动,浏览器访问 http://localhost:7860
```

## 四、软件功能说明与操作

### 4.1 主界面

软件启动后,浏览器打开交互界面,包含两个功能页签:「① 导入会议」与「② 智能问答」。

【此处插入截图:软件主界面,展示两个页签】

### 4.2 会议导入与转写

**功能说明**:将会议音频文件(MP3/WAV/M4A)上传并自动完成转写、分块、向量化、入库的全流程。

**操作步骤**:
1. 点击「① 导入会议」页签;
2. 上传音频文件,填写会议标题(如"组会-2026-08-22")与会议日期;
3. 点击「转写入库」按钮;
4. 系统依次执行:语音识别(ASR)→ 智能分块 → 向量嵌入 → 入库,完成后提示入库的知识块数量。

【此处插入截图:导入会议页签,含音频上传与标题填写】

### 4.3 自然语言智能问答

**功能说明**:用日常口语向知识库提问,系统先检索相关会议内容,再由本地大模型基于检索结果生成回答,答案标注来源段落与时间戳。

**操作步骤**:
1. 点击「② 智能问答」页签;
2. 在输入框输入问题,如"组会里HBase查询变慢的原因是什么?";
3. 回车提交,系统返回回答与来源引用(含时间段与相关度);
4. 支持连续追问,如继续问"那修复方案呢?",系统自动结合上文检索。

【此处插入截图:智能问答页签,展示一个问答结果与引用列表】

## 五、系统架构与技术实现

### 5.1 总体流程

```
会议音/视频 → ASR转写(带时间戳) → 智能分块 → 向量嵌入
    → 向量知识库(Milvus Lite) → 混合检索+重排 → 本地大模型生成 → 带引用回答
```

### 5.2 模块组成

| 模块 | 文件 | 职责 |
|---|---|---|
| 语音识别 | app/asr.py | 基于 faster-whisper(large-v3)转写,输出带时间戳段落 |
| 智能分块 | app/chunk.py | 按语义边界切分,保留时间戳元数据,超长段递归切分 |
| 向量嵌入 | app/embed.py | 基于 bge-large-zh-v1.5 生成 1024 维中文向量 |
| 向量存储 | app/ingest.py | Milvus Lite 建库、增量入库(字符串主键+元数据) |
| 混合检索 | app/retriever.py | BM25(jieba 分词)+ 向量双路召回,RRF 融合,bge-reranker 精排 |
| 智能问答 | app/query.py | 检索→Prompt 组装→生成,多轮对话 query rewriting |
| 本地生成 | app/llm.py | llama.cpp 加载 Qwen2.5-7B GGUF,CPU/GPU 自适应 |
| 交互界面 | app/ui.py | Gradio Web 界面 |
| 检索评测 | app/evaluate.py | 标注测试集量化检索准确率 |

### 5.3 关键技术参数

| 项目 | 参数 |
|---|---|
| 转写模型 | faster-whisper large-v3,int8 量化 |
| 嵌入模型 | bge-large-zh-v1.5,1024 维 |
| 重排模型 | bge-reranker-v2-m3 |
| 生成模型 | Qwen2.5-7B-Instruct,GGUF Q4_K_M 量化(约 4.4GB) |
| 向量数据库 | Milvus Lite(嵌入式,余弦相似度) |
| 检索策略 | 混合检索(向量 20 路 + BM25 20 路)→ RRF 融合 → Rerank 精排 top-30 → 阈值过滤 |
| 性能实测 | 检索准确率 83.3%(标注测试集);单次问答 CPU 约 43 秒,GPU 环境更快 |

## 六、数据安全与隐私

- 全部模型本地加载,推理过程不产生任何网络请求;
- 音频、转写文本、向量数据全部存储于用户本地目录;
- 无云端账号、无数据上传,适用于对数据隐私有要求的机构与个人场景。

## 七、常见问题

| 问题 | 处理方式 |
|---|---|
| 转写结果有错别字 | 转写质量受录音清晰度影响;可后期增加专有名词热词表优化 |
| 问答较慢 | 首次需加载大模型(约 30 秒);后续提问加快;建议 GPU 环境 |
| 模型文件较大 | 模型约 9GB 存储于 models/ 目录,删除后重新下载即可 |
| 如何清理 | 删除 venv/ 与 models/ 目录即可完全卸载 |
